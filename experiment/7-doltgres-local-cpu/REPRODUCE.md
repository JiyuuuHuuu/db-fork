# Reproducing experiment 7

Everything needed to rerun this experiment from scratch: machine, server setup, code version, every parameter,
the commands in order with durations, checks, analysis, cleanup and pitfalls. Paths are relative to the repo root;
`X=experiment/7-doltgres-local-cpu`.

## Machine

| | |
|---|---|
| Host | `dassl-serv-01` (shared lab server, not CloudLab), user `jiyu`, no sudo |
| CPU | 4× Intel Xeon Gold 6418H, 24 cores per socket, **no SMT** (96 CPUs), 4 NUMA nodes. CPU ids are interleaved: node *k* holds *k*, *k*+4, *k*+8, … |
| Memory | 251 GiB (about 64 GB per node) |
| Disks | root LVM (full: 4.5 GB free); 4× Dell 1.92 TB NVMe. Server data on `/mydata` (`nvme2n1`, ext4) |
| OS | Ubuntu 22.04.5, kernel 5.15.0-131-generic |
| Tools | `numactl`, `mpstat` (sysstat), `uv`, Python 3.13 venv of the repo |

Placement (all in `scripts/env.sh`; only NUMA nodes 2 and 3 are used):

| | CPUs | Memory |
|---|---|---|
| Server, 10 cores | node 2: `2,6,10,14,18,22,26,30,34,38` | `--membind=2` |
| Server, 5 cores (core sweep) | `2,6,10,14,18` | `--membind=2` |
| Clients: driver, benchmark processes, CPU agent, read check | the other 14 of node 2 (`42,…,94`) and all 24 of node 3 (`3,…,95`): 38 | `--membind=2,3` |

Client and server talk over TCP loopback (`127.0.0.1:5433`). The machine is shared: before a run, check that
the server's and clients' CPUs are idle (`doltgres_server.sh status` prints `mpstat` for the server CPUs and
the top CPU users).

## Server

- Doltgres **1.4.0** (`https://github.com/dolthub/doltgresql/releases/download/v1.4.0/doltgresql-linux-amd64.tar.gz`),
  the same version as experiment 2, installed under `/mydata/jiyu/doltgres-exp7/` (`$ROOT`) by
  `scripts/doltgres_server.sh install`.
- `$ROOT/config.yaml`: `log_level: warning`, listener `127.0.0.1:5433`, `data_dir: $ROOT/databases`,
  `cfg_dir: $ROOT/.doltcfg`. No `max_connections` / `behavior` keys (1.4.0 rejects them; it accepts 1,025
  connections without).
- Committer identity for `dolt_commit`: `$ROOT/home/.dolt/config_global.json`, found through
  `DOLT_ROOT_PATH=$ROOT/home` (nothing is written to `~/.dolt`).
- Started by `doltgres_server.sh start K` as
  `GOMAXPROCS=K numactl --physcpubind=<first K server CPUs> --membind=2 doltgres -config $ROOT/config.yaml`
  (not under systemd). `numactl` execs the server, so the recorded pid (`$ROOT/doltgres.pid`) is the server's;
  the benchmark reads its CPU from `/proc/<pid>/stat` (`DBFORK_SERVER_PID`). Its log goes to
  `logs/server_<time>_<K>c.log`. Open-file limit inherited from the shell: 1,048,576.

## Parameters

| Parameter | Value |
|---|---|
| N (existing branches, all busy) | 1, 4, 16, 64, 256, 1024; fresh `throughput_bench` database per run |
| Data and branches | CH-benCHmark W=1 (608,435 rows) copied from `ch_w1_seed` (generated by the first run, ~1 min); table `stock`; branches forked from `main` (fan-out), 100 untimed single-row UPDATEs each |
| Data ops | one client per branch, one request in flight (sync); READ (point) and RANGE_READ (100 rows) |
| Ops per client | READ `min(4000, max(50, ⌈200000/N⌉))`, RANGE_READ `min(1000, max(10, ⌈50000/N⌉))`; 10% extra untimed warm-up. (Experiment 2: 40,000 / 10,000 per run, uncapped; raised here for longer timed windows) |
| Branch creation | one client creates 100 branches (10 untimed first) while each of the N branches has a client running point READs back to back (`--background-op READ`; experiment 2: MIXED) |
| Client processes | `min(N, 38)` (data ops), `min(N + 1, 38)` (branch creation) |
| CPU measurement | per run: `server_cpu_cores` (server process, `/proc/<pid>`), `client_cpu_cores` (client processes' rusage) over the timed window; plus `scripts/cpu_agent.py` sampling every CPU of both sets every 0.5 s into `data/dolt/cpu/<run>.csv` and serving `DBFORK_REMOTE_CPU` (`remote_cpu` in the summaries; interpolated from 1 s polls, so coarse for short windows) |
| Read check | `scripts/read_ceiling_check.py`: minimal asyncio client (psycopg 3), 38 processes, N = 64, 256, 1024, point and range, 20 s each, branches `rc_*` on `ch_w1_seed` |
| Core sweep | the read check at N = 256 with the server restarted on 5 cores |

## Commands, in order

```bash
X=experiment/7-doltgres-local-cpu
source $X/scripts/env.sh

# 1. Install and start the server on 10 cores (1 min); record the idle pinning check
$X/scripts/doltgres_server.sh install
$X/scripts/doltgres_server.sh start 10
$X/scripts/doltgres_server.sh status > $X/logs/pinning_idle.log

# 2. Smoke test (3 min; the first run generates ch_w1_seed)
numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM $X/scripts/run_busy_branches.sh --smoke \
    > $X/logs/driver_smoke.log 2>&1
#    pass: every line DONE ... ok; output in data/superseded/smoke_dolt

# 3. Full sweep, detached (39 min: the N = 1,024 branch-creation run alone takes 21 min, 100 creates at ~7 s;
#    the other runs are mostly branch setup at ~4.5 branches/s)
setsid nohup numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM $X/scripts/run_busy_branches.sh \
    > $X/logs/driver_full.log 2>&1 < /dev/null &
tail -f $X/data/dolt/progress.log
#    pass: 18 lines "DONE ... ok", no FAILED / CHECK-FAIL, both md5 lines identical.
#    Optional: doltgres_server.sh status during the N = 256 READ window -> logs/pinning_busy.log

# 4. Read check, server on 10 cores (2 min)
EXP7_SERVER_CPUS=$(server_cpus 10) DBFORK_SERVER_PID=$(server_pid) \
    numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM uv run python $X/scripts/read_ceiling_check.py \
    --ns 64,256,1024 --out $X/data/dolt/read_check.csv > $X/logs/read_check_10c.log 2>&1

# 5. Core sweep: server on 5 cores, read check at N = 256 (2 min), then back to 10
$X/scripts/doltgres_server.sh stop && $X/scripts/doltgres_server.sh start 5
EXP7_SERVER_CPUS=$(server_cpus 5) DBFORK_SERVER_PID=$(server_pid) \
    numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM uv run python $X/scripts/read_ceiling_check.py \
    --ns 256 --out $X/data/dolt/read_check_5c.csv > $X/logs/read_check_5c.log 2>&1
$X/scripts/doltgres_server.sh stop

# 6. Figures and tables (1 min)
uv run python $X/scripts/plot_busy_branches.py --run-dir $X/data/dolt --server-cores 10 --client-cores 38 \
    --read-check $X/data/dolt/read_check.csv --read-check $X/data/dolt/read_check_5c.csv \
    --mixed-dir $X/data/dolt/branch_create_mixed --outdir $X/figures
uv run python $X/scripts/cpu_window.py
```
(`--mixed-dir` adds the 80/20 follow-up below; leave it out before that follow-up has run.)

## Follow-up: branch creation, reads against CPU (15 min)

1,024 busy branches with one point-read connection each, reads back to back or paced to a total rate, branch
creations timed from one more connection; the server on 10 or 20 cores of node 2 (20: `2,6,…,78`), the clients on
the other 28 cores of nodes 2-3 (`CLIENT_CPUS_28`). `run_create_under_reads.sh P` runs P0 (10 cores, back to back,
30 creates), P2 (10 cores, paced to half of P0's measured rate, 100), then restarts the server on 20 cores for P1
(paced to P0's rate, 100) and P3 (back to back, 30). Results append to `data/dolt/create_under_reads*.csv`.

```bash
X=experiment/7-doltgres-local-cpu; source $X/scripts/env.sh
PY="numactl --physcpubind=$CLIENT_CPUS_28 --membind=$CLIENT_MEM uv run python $X/scripts/create_under_reads.py"
$X/scripts/doltgres_server.sh start 10
$PY setup --n 1024                                  # plain branches rc_0..rc_1023 (2 s)
$X/scripts/run_create_under_reads.sh C > $X/logs/create_under_reads_C.log 2>&1     # 2 min
$X/scripts/doltgres_server.sh stop; $X/scripts/doltgres_server.sh start 10
$PY cleanup --n 1024
$PY setup --n 1024 --updates 100                    # 100 uncommitted UPDATEs per branch, like the benchmark (80 s)
$X/scripts/run_create_under_reads.sh D > $X/logs/create_under_reads_D.log 2>&1     # 5 min
$PY cleanup --n 1024; $X/scripts/doltgres_server.sh stop
```

Pass: P1 reads/s within 1% of P0's; P1 and P2 server CPU well below the core count; P0 and P3 at it.

## Follow-up: branch creation with an 80% read / 20% update background (2 min)

Experiment 7's setup unchanged (server on 10 cores, clients on 38, same driver and data); only the busy branches'
workload is experiment 2's MIXED (80% point reads, 20% updates). Run 25 Oct 2026.

```bash
X=experiment/7-doltgres-local-cpu; source $X/scripts/env.sh
$X/scripts/doltgres_server.sh start 10
numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM $X/scripts/run_busy_branches.sh --smoke \
    --phases branch_create --background-op MIXED > $X/logs/driver_smoke_mixed.log 2>&1        # 30 s
numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM $X/scripts/run_busy_branches.sh \
    --phases branch_create --ns 1,4,16 --background-op MIXED > $X/logs/driver_create_mixed.log 2>&1   # 45 s
for r in r2 r3; do   # repetitions (45 s each)
  numactl --physcpubind=$CLIENT_CPUS --membind=$CLIENT_MEM $X/scripts/run_busy_branches.sh \
      --phases branch_create --ns 1,4,16 --background-op MIXED --outroot $X/data/dolt/repeats_mixed/$r \
      > $X/logs/driver_create_mixed_$r.log 2>&1
done
$X/scripts/doltgres_server.sh stop
```

Pass: 3 lines "DONE ... ok" per driver log, both md5 lines identical (and equal to the main sweep's); in the
parquet the background rows are about 80% READ / 20% UPDATE statements. Output: `data/dolt/branch_create_mixed/`
(plotted), `data/dolt/repeats_mixed/r2|r3/branch_create_mixed/`, CPU samples `cpu/create_mixed_n<N>.csv`.

## Cleanup

`$X/scripts/doltgres_server.sh stop`. The server tree `/mydata/jiyu/doltgres-exp7/` (binary, `ch_w1_seed`,
about 0.2 GB) can stay for a rerun or be removed with `rm -rf /mydata/jiyu/doltgres-exp7`.

## Pitfalls

- **Root disk is full.** Only results go in the repo; the server binary, data and pid file live on `/mydata`.
- **Never create `.env`** in the repo: another experiment runs from the same checkout. The scripts export
  `DOLT_HOST`, `DOLT_PORT`, `DOLT_DATA_DIR` themselves and unset `DBFORK_SERVER_HOST`, `DBFORK_SERVER_SSH`,
  `DBFORK_PREWARM_SQL`.
- **`DOLT_DATA_DIR` must be the server's real data dir**: `scripts/run_throughput_bench.sh` empties
  `$DOLT_DATA_DIR/.dolt_dropped_databases` after each run.
- **Parquet files append by run id.** READ and RANGE_READ at one N share `dolt_chw1_tp_t<N>_b<N>.parquet`
  (`cpu_window.py` splits them by SQL text). A rerun must go to a new `--outroot` or delete the old files first.
- **The driver refuses to run** if its CPU set includes a server CPU or the server's core count differs from
  `--server-cores`; it holds `$ROOT/driver.lock` so two drivers never share `throughput_bench`.
- **GOMAXPROCS** is fixed at start (and also taken from the affinity mask); change the core count only by restart.
- **Short windows.** READ at N ≤ 16 has 2-2.5 s windows and the branch creations 0.1-0.6 s; use the exact
  `server_cpu_cores` / `client_cpu_cores`, not the interpolated `remote_cpu`, for those.
- **Driver logs are `*.log`**: `**.out` is gitignored.
- **The server can die after the N = 1,024 branch-creation run.** Its 1,024 background readers record 16 million
  reads; merging 35 million rows (1.2 GB parquet) took the client's memory on nodes 2-3, and the server (memory
  bound to node 2) disappeared without a log message, probably OOM-killed (kernel log needs root). The run's data
  were complete. Check `doltgres_server.sh status` and restart before the read check. Mind the root disk: that
  parquet is on it.
